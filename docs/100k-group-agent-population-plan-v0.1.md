# 10 万“微型群体 Agent”画像构建方案 v0.1

## 1. 目标与统计单位

本项目不把一个 Agent 解释为一个真实网民，而把它定义为一个**带权重的微型群体单元**：成员在平台、账号角色、兴趣组合、信息来源、活跃节律、传播行为和表达风格上相近。Agent 的 `population_weight` 表示它代表的群体规模。

仿真输出不是“Agent 做了一个动作”，而是该群体在一个时间步内产生的加权人数或账号数，例如曝光量、参与账号数、转发数、评论数和原创数。这样既保留群体异质性，也避免制造 10 万个看似具体、实则无数据依据的虚构个人。

第一阶段的参考总体应限定为：**现有平台中可观测的内容生产与事件传播群体**。现有数据不足以直接代表全部网民，尤其缺少沉默浏览者和普通低粉用户。若未来要模拟完整网民总体，需要补充平台人口结构、消费行为或抽样调查数据。

## 2. 现有数据能支持什么

### 第一次采集：头部账号与历史作品

- 10 万个不重复头部账号，适合学习平台、影响力层级、账号类型和内容生产偏好。
- 约 217.9 万条作品，但只有约 1.89 万账号有作品记录，不能把“无作品”直接解释为“不感兴趣”。
- 账号粉丝数最低约 122 万，样本明显偏向头部生产者，不能直接充当普通网民分布。
- 标题和封面文本较完整，OCR 和 ASR 覆盖不足，内容理解应采用多字段融合并记录缺失置信度。

### 第二次采集：298 个事件的参与账号与内容

- 298 个事件目录，约 23.7 万条账号—事件记录、14.65 万个独立账号、43.56 万条内容记录。
- 适合学习账号参与哪些事件、何时进入、重复发布、跨事件活跃、平台迁移和传播节律。
- 数据明显偏向微博，且存在空事件和重复/高度相似事件，拆分训练集前必须先做事件族去重。

### 明确的数据边界

现有数据观测到的是“发布和参与”，没有单用户级点击、停留、完播、快速划走和真实关注边。因此：

- 发布偏好、事件参与偏好：可由数据估计；
- 浏览偏好、社交关系、曝光概率：只能通过代理变量估计或作为实验假设；
- 所有字段必须标注 `observed / estimated / assumed` 及置信度，不能混写成事实。

## 3. Agent 画像的六个切面

每个群体 Agent 由六组互相关联的特征组成，而不是一张虚构人物简历。

1. **基础身份**：主要平台与跨平台组合、账号角色、影响力层级、地域层级、机构/个人属性。
2. **兴趣结构**：多主题概率分布，而非单一标签；同时记录长期兴趣、事件兴趣和兴趣多样性。
3. **信息饮食**：偏好权威媒体、垂类作者、熟人网络、热榜或算法探索的比例，以及来源信任向量。
4. **行为节律**：活跃时段、发帖频率、爆发性、进入事件的早中晚倾向、重复发帖和疲劳速度。
5. **传播心理**：从众敏感度、新奇偏好、情绪唤醒敏感度、核验倾向、立场一致性、风险厌恶。
6. **表达与作品偏好**：原创/转发/评论比例，标题长度、情绪强度、叙事方式、媒体形态和改写风格。

年龄、性别、职业等属性只有在存在可靠观测或可校准的外部分布时才加入；否则不应为了“丰满”而编造。丰满来自行为维度间的一致性，而不是虚构个人故事。

## 4. 从多角度间接推断偏好

对每个真实账号先形成证据向量，再学习群体分布：

- **发了什么**：标题、简介、OCR、ASR、作者标签形成主题与风格向量；
- **参加了什么**：跨 298 事件的参与矩阵形成事件兴趣和议题广度；
- **何时参加**：相对事件起点的进入延迟区分首发者、放大者和跟随者；
- **如何参加**：原创、重复发布、疑似转载、评论式表达形成传播角色；
- **谁与其相似**：内容相似、共同参与事件和时间同步形成同群关系；
- **跨越了什么圈层**：连接不同主题或平台的账号形成桥接倾向；
- **没有参加什么**：只作为弱负证据，并进行贝叶斯收缩，避免把采集缺失误判为厌恶；
- **受欢迎程度**：互动指标在平台内归一化后估计作品吸引力，不能跨平台直接比较原始数值。

推荐系统中的隐式反馈思想会被转化为群体级机制：相似群体的行为用于协同过滤；内容与群体使用共享主题空间匹配；少量推荐位承担探索；群体对曝光的响应会反过来更新短期兴趣。但没有真实消费日志的部分必须通过 298 个事件曲线反向校准，不能声称来自直接观测。

## 5. 构建管线

### 阶段 A：定义口径和真值

1. 将主验证指标定为每 30 分钟新增与累计独立参与账号数；帖子数为次指标。
2. 明确 10 万 Agent 的权重总和代表什么总体，并为不同平台分别设定归一化口径。
3. 对 298 个事件做事件族聚类，合并或绑定重复事件，防止同源事件跨训练/测试集泄漏。

### 阶段 B：建立统一事实层

生成五张不可变基础表：

- `account_canonical`：去重账号、平台、影响力和观测字段；
- `content_canonical`：去重作品、作者、时间、文本和互动；
- `event_catalog`：事件时间窗、主题、类型、规模和事件族；
- `account_event_fact`：账号进入时间、发布次数、内容角色和平台；
- `event_truth_curve`：每个事件的真实分桶曲线与参与者结构。

统一处理平台字段、异常值、重复资源、缺失作者和跨平台指标；保留原始值、清洗值与变换规则。

### 阶段 C：学习真实账号的潜在表征

1. 用多语义字段建立内容主题向量与事件向量。
2. 为账号计算主题分布、发布节律、事件参与广度、进入延迟、原创度、重复度、桥接度等特征。
3. 使用层次混合模型或变分模型学习联合分布；避免逐列独立随机采样破坏真实相关性。
4. 先得到约 300–1,000 个稳定“群体原型”，并为每个原型保存规模、均值、方差和协方差。

### 阶段 D：生成 10 万个带权群体 Agent

1. 按平台 × 角色 × 影响力层 × 主题群 × 活跃节律分层抽样。
2. 在每个原型内部从联合分布采样，生成差异化群体单元。
3. 为每个 Agent 分配 `population_weight`，通过迭代比例拟合使总体边际分布与目标分布一致。
4. 对低粉普通传播者和沉默浏览者建立“假设层”，与真实头部样本分开保存，并可在实验中关闭。
5. 生成自然语言“群体卡片”仅作为结构化字段的解释视图，不作为模型的真实输入。

### 阶段 E：构建多层网络

网络不是伪造一张精确关注图，而是构造可校准的多层有向加权图：

- 关注/可达层：由平台、影响力和同质性决定；
- 兴趣近邻层：由主题相似度决定；
- 事件共参与层：由 298 个事件中的共现与时间同步决定；
- 跨平台桥接层：连接平台间的搬运者和议题桥梁。

推荐采用度修正随机分块模型（DC-SBM）。边权表示预期触达强度与信任，不宣称是真实用户关系。

### 阶段 F：群体级推荐和行为模型

每个时间步先从关注、兴趣、热榜、搜索和探索五个通道召回候选，再以关系、兴趣、热度、新鲜度、来源信任、立场匹配、探索奖励和疲劳惩罚排序。

对群体 Agent 使用计数分布而非单次抽签：

- 曝光人数：二项或 Beta-Binomial；
- 点击/深度阅读：条件概率模型；
- 转发、评论、原创：零膨胀计数模型；
- 个体差异：通过群体内离散度和随机效应保留。

语言模型只用于少量需要语义判断或生成改写文本的节点；大规模动力学由可复现概率模型承担。

### 阶段 G：用 298 个事件校准与验证

1. 按事件族和时间切分训练、验证、测试集，禁止相似事件泄漏。
2. 先校准全局参数，再校准平台、事件类型和群体原型的层次参数，不为每个事件单独调一套参数。
3. 优化目标同时包含曲线距离、T10/T50/T90、峰值与峰时、平台占比、参与者画像、重复发帖率和集中度。
4. 每组参数运行多个随机种子，报告中位数和 10%–90% 区间。
5. 对空事件、超大事件、突发事件和跨平台事件分别报告误差，避免平均值掩盖失败案例。

## 6. 10 万 Agent 的建议数据结构

```text
agent_id
archetype_id
population_weight
platform_mix
account_role
influence_tier
region_bucket
topic_distribution
source_trust_vector
active_hour_distribution
posting_rate / browsing_capacity
original_repost_comment_mix
early_entry / social_proof / novelty / emotion / verification
fatigue_rate / memory_decay
network_community / bridge_score
profile_provenance
profile_confidence
```

运行期另存短期兴趣、事件记忆、曝光次数、疲劳和当前立场，避免将动态状态固化到初始身份。

## 7. 质量门槛

生成的 10 万 Agent 至少通过以下检查后才可用于传播仿真：

- 平台、角色、影响力、主题和活跃时段的加权边际分布与目标一致；
- 关键联合关系得到保留，例如“平台—题材”“影响力—发帖率”“角色—原创率”；
- 群体原型之间可区分，原型内部仍有合理方差；
- 任意字段可追溯到观测、估计或假设来源；
- 删除任一假设层后可做消融实验；
- 固定随机种子可重建同一人口快照与网络快照；
- 不包含可识别个人信息，也不把合成画像展示为真实账号。

## 8. 迭代顺序与验收物

不要直接在 10 万规模上调参。建议顺序：

1. **数据基线**：完成统一事实层和 298 条真实曲线；
2. **画像原型**：形成 300–1,000 个原型及可解释报告；
3. **1 万群体试运行**：选 20 个互不相似事件、48 个时间步，验证口径和动力学；
4. **10 万人口快照**：只验证分布、权重和网络，不先启用文本生成；
5. **298 事件回放**：完成训练/验证/测试与多随机种子评估；
6. **多事件竞争世界**：再开启 298 个事件共同争夺注意力。

核心交付物：

- `agent_archetypes.parquet`
- `population_snapshot_100k.parquet`
- `network_edges.parquet`
- `event_truth_curves.parquet`
- `parameter_registry.yaml`
- `population_quality_report.json`
- `simulation_validation_report.json`

## 9. 第一轮实施建议

第一轮先完成“事实层 + 群体原型”，不要立即生成最终 10 万画像。其验收标准是：能从任意一个原型追溯到支撑它的真实统计特征，能展示它在不同事件类型中的进入时间与发布倾向，并能说明哪些特征来自观测、估计和假设。完成这一层后，10 万 Agent 只是可复现的分层采样和权重校准问题，而不是继续手工编写 10 万份设定。
